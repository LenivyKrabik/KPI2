# Наміри

Мені потрібно створити діаграму яка детальніше описує процес одного з usecase. На цю роль я обрав: **UC2 - покращення аккаунту до рівня дослідника**, як і в минулій лабі.

# Деталізація Usecase

## Вибір форми опису:

**Вибрано:** Activity diagram
**Обгрунтування:** Вейсь процес можна зручно описати послідовністю дій, та він відбувається (за виключенням вводу користувача) повністю всередині системи

## Кроки:

Загальний нарис кроків взятий з Squence diagram з минулої роботи, заради збереження цілісності, та змінений під цю схему.

## Ролі:

Ролі також взяті з Squence diagram з минулої роботи, проте, осікльки activity diagram призначена скоріш для менеджерів, а не спеціалістів, я поєднав frontend та backend в одну роль - система

- Користувач (без аккаунта дослідника)
- Система
- Orchid
- Scopus

# Критерії прийому

- Логіка повна (повнота переходів, досяжність станів, коректність умов)
- Присутні всі необхідні для завдання елементи (початок, кінець, ≥1 розгалуження й ≥1 паралельна гілка. Є ≥1 надсилання повідомлення з показаною реакцією на відповідь або її відсутність)
- Обгрунтування вибору форми
- Узгодженість з UC/Sequence
- Для кожного повідомлення — хто надсилає, хто приймає, що робить процес без відповіді

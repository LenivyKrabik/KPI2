# Як організувати верифікацію дослідника

## Context and Problem Statement

Користувач хоче повищити свій аккаунт до рівня дослідника. Яким чином краще організуват його верифікацію?

## Considered Options

- Обійтись без підтверджень та просто прийняти кожного користувача хто забажає повищити свій статус
  - Плюс - Не треба робити складних систем, які понесуть за собою крихкість системи
  - Плюс - Платформа стане доступнішою для всіх користувачів
  - Мінус - не буде ніяких обмежень для того хто хоче бути дослідником, що може спричинити багато спаму та неприємлимого контенту в дослідженнях
- Логін через OrcidID/ScopusID/Google Scholar
  - Плюс - фільтрація користувачів які можуть створювати дослідження проходить іншою, довіреною, організацією
  - Плюс - дає можливість підв'язати аккаунт досвлідника до нього, що допоможе іншим дізнатися про нього більше
  - Мінус - складніший процес авторизації
  - Мінус - обмеження для дослідників які не мають відповідного аккаунта

## Decision Outcome

Прийнято рішення зробити авторизацію через Orcid та Google Scholar, та прив'язати аккаунт Scopus якщо він існює, осікльки з даних перших двох сервісів можна отримати дані про аккаунт Scopus. Можливість скинутої модерації дослідників, хоч і не приберає, але спрощує роботу для системи фільтрації, та не є такою вже й проблемою для використання сервіса для цільової аудиторії (дослідники)

## Results

- Плюс - фільтрація користувачів які можуть створювати дослідження проходить іншою, довіреною, організацією
- Плюс - дає можливість підв'язати аккаунт досвлідника до нього, що допоможе іншим дізнатися про нього більше
- Мінус - складніший процес авторизації
- Мінус - обмеження для дослідників які не мають відповідного аккаунта
